# T-04 — Onde cada CLI guarda credencial: medido aqui, roteiro para Windows

## 1. Objetivo
Depois de você terminar, existe
`orquestracao/spikes/credenciais.md` com uma tabela do que foi **medido
nesta máquina Linux** (comando e saída colados) e, em seção separada, o
roteiro exato para rodar numa máquina Windows quando houver uma.

## 2. Caminhos absolutos
- criar: `/home/nicolas/Área de trabalho/esteira/orquestracao/spikes/credenciais.md`
- leia: `/home/nicolas/Área de trabalho/esteira/esteira/contas.py` (`VAR_CONFIG`, `env_para`)
- leia: `/home/nicolas/Área de trabalho/esteira/contas.yaml` (o comentário explica a intenção)
- leia: `/home/nicolas/Área de trabalho/esteira/README.md`, seção "Se a credencial foi COPIADA em vez de logada"

## 3. Escopo
Só `orquestracao/spikes/**`. Qualquer arquivo fora disso é violação.

## 4. O que NÃO tocar
Nada fora de `orquestracao/spikes/`.
**E o mais importante: NÃO ABRA, NÃO LEIA, NÃO COPIE E NÃO IMPRIMA o
conteúdo de nenhum arquivo de credencial.** Você pode listar nome,
tamanho e permissão de arquivo. Nunca o conteúdo. Nada de
`cat ~/.esteira-auth/...`, nada de `cat ~/.claude/.credentials.json`.

## 5. Prova exigida
Cada linha da tabela precisa ter o comando que a produziu e a saída
colada. Exemplo do que serve:

    ls -la ~/.esteira-auth/nicolas/claude/
    ls -la ~/.esteira-auth/nicolas/codex/

Linha sem comando e saída não vale — apague em vez de deixar sem prova.

## 6. Relatório
O próprio `credenciais.md` é o entregável. No fim dele, uma seção
"O que não deu para medir" dizendo o que exige a máquina Windows.

## 7. Detalhes que importam
- Os 4 runtimes são: `claude`, `codex`, `opencode`, `agy`.
- O que já se sabe e você deve confirmar, não redescobrir:
  `claude` usa `CLAUDE_CONFIG_DIR`; `codex` usa `CODEX_HOME`;
  `opencode` e `agy` **não têm** variável de config-dir em `contas.py`.
- O que interessa por runtime: **onde mora o token** (arquivo? keyring do
  sistema?), **se aceita variável para trocar o diretório**, e **se o
  arquivo sobrevive a reboot**. Sobre reboot você provavelmente só pode
  raciocinar a partir de onde o arquivo está — diga que é inferência e não
  medição.
- **A pergunta que decide o desenho do nó Windows:** se a credencial de um
  CLI mora no *keyring* do usuário (no Windows, o Credential Manager via
  DPAPI), então **nenhum serviço rodando como SYSTEM consegue usá-la**, e o
  nó tem que rodar como Tarefa Agendada sob o usuário interativo. Escreva
  essa conclusão explicitamente para cada runtime, com o que sustenta ela.
- **Não invente medição de Windows.** Não há máquina Windows aqui. A seção
  de Windows é **roteiro**: os comandos exatos, o que olhar, e uma tabela
  vazia para preencher. Se você escrever um resultado de Windows como se
  tivesse medido, a tarefa falhou.
- PT-BR. Palavra estrangeira em itálico: *keyring*, *token*, *reboot*.
